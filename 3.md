# Texel AI — что уже реализовано

Исчерпывающий перечень готового функционала платформы по состоянию на **2026-05-21**.

---

## 1. Архитектура и инфраструктура

- **Микросервисная архитектура** из 4 сервисов, поднимаемых одной командой `docker compose up --build`:
  - `frontend` — React + Vite + TypeScript, отдаётся через Nginx на порту `80`.
  - `backend` — Express + SQLite, порт `3001`, REST API.
  - `ai-chat-service` — FastAPI + httpx, порт `8001`, обёртка над OpenRouter.
  - `news-service` — Express + rss-parser + cheerio, порт `8002`.
- **Nginx-конфиг** ([nginx.conf](nginx.conf)) — раздаёт SPA и проксирует запросы на бэкенды.
- **Единая точка конфигурации** через корневой `.env` (`OPENROUTER_API_KEY`).
- **Dockerfile под каждый сервис** + общий `docker-compose.yml`.
- **TanStack Query** для серверного состояния и кеширования.
- **React Router v6** — SPA-роутинг с catch-all 404.

---

## 2. Авторизация и сессии

- **Регистрация** (`POST /api/auth/register`) с проверкой уникальности логина/email.
- **Вход** (`POST /api/auth/login`) — по логину **или** email + пароль.
- **Хэширование паролей** через `bcrypt` (12 раундов).
- **Серверные сессии** в таблице `sessions`, идентификатор — 32 байта случайных hex.
- **HttpOnly cookie** `texel_session`, `sameSite=lax`, срок жизни 30 дней.
- **Получение текущего пользователя** — `GET /api/auth/me`.
- **Обновление профиля** — `PATCH /api/auth/me` (имя, email).
- **Выход** — `POST /api/auth/logout` с удалением сессии из БД.
- **Серверная валидация** через `zod` (минимум 6 символов пароля, валидный email, длина имени и логина).
- **React AuthContext** ([AuthContext.tsx](src/contexts/AuthContext.tsx)) — глобальное состояние пользователя, методы `login`, `register`, `logout`, `updateUser` + управление модалками.
- **Toast-уведомления** на каждом действии (вошли / вышли / профиль обновлён).

---

## 3. Роли и контроль доступа

- Две роли: **`user`** и **`admin`** (поле `role` в БД, дефолт — `user`).
- **Серверный guard** `requireAdmin()` — возвращает `403`, если роль не admin.
- **Серверный guard** `requireUser()` — возвращает `401`, если нет сессии.
- **Клиентский guard** в [Admin.tsx](src/pages/Admin.tsx) — редирект на `/`, если пользователь не админ.
- **Защита от самоудаления**: админ не может удалить собственный аккаунт.

## 6. Админ-панель

Страница [/admin](src/pages/Admin.tsx), доступ только роли `admin`:

- **Список пользователей** (`GET /api/admin/users`) — таблица: ID, логин, email, имя, роль, прогресс, дата создания.
- **Inline-редактирование** имени, роли и прогресса прямо в таблице.
- **Сохранение** (`PATCH /api/admin/users/:id`) с индикатором «Сохраняю…».
- **Удаление** (`DELETE /api/admin/users/:id`) с подтверждением через `confirm()`.
- Сортировка по дате создания (новые сверху).
- Отображение ошибок в красной плашке поверх таблицы.

## 7. Обучение (Training)

- **Каталог модулей** ([/training](src/pages/Training.tsx)) — данные из [training-data](src/data/).
- **Страница урока** ([/training/:topicId](src/pages/TrainingLesson.tsx)) — текст, материалы, переход к тесту.
- **Тестирование** ([/training/:topicId/test](src/pages/TrainingTest.tsx)) — вопросы по теме, подсчёт результата.
- **Сохранение результатов** (`POST /api/training/:topicId/test-result`) — UPSERT в таблицу `test_results` по уникальной паре `(user_id, topic_id)`.
- **Получение одного результата** (`GET /api/training/:topicId/test-result`).
- **Получение всех результатов** (`GET /api/training/test-results`) — список всех пройденных тестов с сортировкой по дате.
- **Цветовая индикация** результата: ≥80% — зелёный, ≥50% — жёлтый, <50% — красный.
- **Прогресс пользователя** (`progress` 0–100) хранится в `users`, отображается на профиле и в админке.

## 8. Vibe Coding — встроенная IDE

Страница [/vibe-coding](src/pages/VibeCoding.tsx):

- **Monaco Editor** (движок VS Code), загрузка с CDN, тема `vs-dark`, подсветка синтаксиса.
- **Fallback на `<textarea>`** — если Monaco не загрузился, страница остаётся рабочей.
- **Переключатель языка**: HTML/JS/CSS ↔ Python.
- **Запуск HTML** — рендерится в iframe с `sandbox="allow-scripts"`, предзагружены **p5.js** и **three.js** через CDN.
- **Запуск Python** — выполняется в браузере через **Pyodide (WebAssembly)** с библиотеками `numpy`, `pandas`, `matplotlib`.
- **Matplotlib-графики** — захватываются в PNG (бэкенд `agg`) и встраиваются в превью.
- **Захват stdout / stderr** Python — выводится в `<pre>` под графиком.
- **Индикатор статуса**: `Готово` / `Запуск...` / `Ошибка: ...`.
- **Плавающий AI-чат** снизу справа (тот же ассистент, что и на других страницах).

## 9. AI-чат (ассистент-наставник)

- **Микросервис на FastAPI** ([ai-chat-service/main.py](ai-chat-service/main.py)).
- **Эндпоинт** `POST /chat` — принимает `message`, `conversation_id`, `temperature`.
- **Эндпоинт** `GET /health` — проверка состояния.
- **Провайдер**: OpenRouter с авто-маршрутизатором `openrouter/free` (выбирает быструю бесплатную модель).
- **Системный промпт** — наставник Texel AI на русском, объясняет понятно и поддерживает.
- **Память диалога** — по `conversation_id` хранится контекст беседы.
- **Плавающая кнопка чата** ([AIChat](src/components/AIChat.tsx)) — на главной, training, vibe-coding.
- **Встраиваемая версия** ([EmbeddedAIChat](src/components/EmbeddedAIChat.tsx)) — для размещения внутри страниц.

## 13. База данных (SQLite)

Файл [server/storage.js](server/storage.js):

| Таблица | Поля |
|---|---|
| `users` | `id, username (UNIQUE), email (UNIQUE), password_hash, name, role, progress, created_at` |
| `sessions` | `session_id, user_id, created_at, expires_at` |
| `test_results` | `user_id, topic_id, score, total, percentage, updated_at` (UNIQUE по `user_id + topic_id`) |

## 14. Безопасность

- bcrypt-хэширование паролей (12 раундов).
- HttpOnly + sameSite=lax cookies (защита от XSS-кражи и базового CSRF).
- Zod-валидация всех входных данных API.
- Guard'ы `requireUser` / `requireAdmin` на защищённых эндпоинтах.
- Sandbox-iframe в Vibe Coding (`sandbox="allow-scripts"`).
- Запрет на самоудаление администратора.
- Нормализация логина и email к нижнему регистру при регистрации и входе.

## 15. Сценарии работы

### Сценарий 1 — Новый студент
1. Заходит на `/`, видит Hero, About, Benefits, Program, News.
2. Жмёт «Регистрация» → заполняет форму → попадает в систему с ролью `user`.
3. Переходит в `/training`, выбирает модуль.
4. Изучает урок, проходит тест, видит свой результат с цветовой подсказкой.
5. Прогресс отображается в профиле.

### Сценарий 2 — Уже зарегистрированный пользователь возвращается
1. Открывает сайт — сессия по cookie ещё активна, `GET /api/auth/me` возвращает профиль.
2. Видит свой аватар-инициал в навигации.
3. Продолжает обучение с того места, где остановился — все пройденные тесты сохранены.

### Сценарий 3 — Работа в Vibe Coding
1. Переходит в `/vibe-coding`.
2. Выбирает Python, пишет код с `matplotlib`, жмёт `Run`.
3. Pyodide компилирует и выполняет код в браузере, график появляется в превью справа.
4. Открывает плавающий AI-чат, спрашивает у наставника, как улучшить визуализацию.

### Сценарий 4 — Использование AI-наставника
1. На любой странице жмёт плавающую кнопку чата.
2. Задаёт вопрос — фронт отправляет `POST /chat` с `conversation_id`.
3. FastAPI-сервис добавляет системный промпт и отправляет в OpenRouter (`openrouter/free`).
4. Ответ возвращается студенту, история диалога сохраняется на сервисе для контекста.

### Сценарий 5 — Настройка под себя
1. Заходит в `/profile`, меняет имя и email, сохраняет.
2. Переходит в `/settings`, выбирает тёмную тему, английский язык, включает автопереход.
3. Настройки сохраняются в `localStorage` и переживают перезагрузку страницы.

### Сценарий 6 — Администратор управляет пользователями
1. Заходит как `admin`, видит дополнительный пункт меню «Админ».
2. На `/admin` видит таблицу всех пользователей.
3. Меняет роль одного из пользователей с `user` на `admin`, жмёт «Сохранить».
4. Удаляет тестовый аккаунт — подтверждает действие в `confirm`-диалоге.

### Сценарий 7 — Локальный запуск платформы
1. Разработчик клонирует репозиторий.
2. Создаёт `.env` с `OPENROUTER_API_KEY`.
3. Запускает `docker compose up --build`.
4. Открывает `http://localhost` — все 4 сервиса связаны и работают.

### Сценарий 8 — Чтение свежих новостей про ИИ
1. На главной странице блок News запрашивает данные у news-сервиса.
2. Сервис парсит RSS Habr и возвращает карточки с заголовком, описанием и картинкой.
3. Если в RSS картинки нет — подставляется случайное изображение из локального fallback-набора.
